# 产物标签与检索

每份 `视频总结.md` 顶部添加简单 YAML 元数据；五个正文二级章节继续保留。元数据是分类、标签和索引摘要的唯一维护来源，`产物索引.md` 由脚本重建，不单独手工维护。

```yaml
---
title: "做视频包装如何建立自己的视觉素材参考图鉴"
category: "AI内容创作"
tags: ["视频包装", "视觉素材库", "运镜", "动效", "提示词"]
summary: "把视觉风格与专业动效整理成带示例和提示词的参考库，通过白模与风格重组形成个人特色。"
---
```

- `title` 保留视频原始标题。`category` 是一个简短主分类，跨领域信息放进标签，不另建分类目录或复制产物。
- 每份使用 3–8 个标签，描述实际涉及的主题、方法或明确提到的工具。先查当前索引复用已有称呼，避免“AI剪片/AI剪辑”等同义标签分裂；不加“爆款”“高价值”等无证据评价。
- `summary` 用一句话概括已取得的内容，帮助筛选；部分解析必须限定为页面摘要或现有证据，不把工具的宣传或作者观点写成已验证事实。
- 平台、作者、处理状态仍放在正文的 `视频信息`；索引读取这些字段，不将它们混作主题标签。不猜发布时间，也不新增不明来源的日期。
- 为保持零额外依赖，脚本读取简单 YAML：字符串使用 JSON 兼容的双引号和转义，标签使用上例的 JSON 数组，或每行 `  - "标签"`；不使用多行字符串、单引号、锚点等扩展语法。
- `口播稿.txt` 不添加标签或元数据。更新已有产物时只修改元数据，保留正文；用户已维护的元数据不自动重标。

完成单视频或批量交付，或修改标题、分类、标签、摘要、交付路径后，从实际使用工作区运行：

```powershell
python <skill-path>/scripts/index_outputs.py
```

默认只读 `.video-summary-radar/outputs/*/视频总结.md` 和其批次的 `*/digests/*/视频总结.md`，按分类、标题稳定排序；只为实际存在的口播稿生成链接，部分解析也入索引并保留状态。遇到缺少必需元数据的总结会报出路径，补齐后重跑，不默默遗漏。不进入处理资料、媒体或运行环境。自定义输出位置用 `--output-root "<产物根目录>"`。

检索先查 `产物索引.md`，也可运行只读查询：

```powershell
python <skill-path>/scripts/index_outputs.py --query "运镜 提示词"
```

多个词以空格分隔，全部匹配，不区分英文大小写；查询范围为标题、分类、标签、摘要、作者和平台。查询不改写索引。索引未命中时可扩大到总结与口播的全文搜索，再据实际内容补充合理标签；主题相似不代表事实已核实。

读取顺序：索引 → 命中的视频总结 → 需要精确引用时读口播稿 → 需要核对时读处理资料。工作区被 Git 忽略时，使用明确路径，全文搜索加 `rg --no-ignore --hidden` 并限定 `视频总结.md` 或 `口播稿.txt`，排除 `处理资料` 和 `处理记录`；不扫描整个仓库及运行环境。

从使用工作区执行全文搜索示例（`-l` 只列出命中的文件）：

```powershell
rg --no-ignore --hidden -l "运镜|提示词" .video-summary-radar/outputs -g "视频总结.md" -g "口播稿.txt" -g "!**/处理资料/**" -g "!**/处理记录/**"
```
