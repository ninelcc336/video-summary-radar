# 输出模板

最终中文 Markdown 内容包使用以下固定章节顺序，只整理视频已有内容。用户仅要求字幕、逐字稿等特定格式时，按其要求交付，不强制扩展为完整内容包。

```markdown
# 视频内容包

## 基本信息

- 标题：
- 来源：
- 链接或文件：
- 时长：
- 证据来源：口播 / 字幕 / 页面内容 / 关键画面
- 内容覆盖度：主要内容已确认的估计比例
- 处理说明：

## 结论速览

用约一分钟可读完的篇幅，直接回答：视频解决什么问题、结论是什么、怎么做、主要依据是什么、有什么重要限制。不要用时间线替代总结。

## 完整内容还原

按主题和论证逻辑重组内容，通常依次说明问题背景、核心判断、方法或步骤、案例/证据、结论。让读者不看原视频也能理解，不机械复述口头语或镜头顺序。

### 问题与结论

说明视频试图回答的问题与最终判断。区分视频原话、可核验事实和编辑归纳。

### 方法、过程与关键步骤

把可执行步骤、条件、输入输出和关键决策写清楚；涉及演示时说明操作流程。

### 证据、案例与推理链

记录作者用来支撑结论的案例、数字、对比或因果推理，并标明哪些是作者观点而非已验证事实。

## 关键画面与操作

只收录对理解不可替代的画面：PPT、代码、图表、界面操作、步骤状态或前后对比。每项写明画面信息及其解释；仅在必要时链接 3-8 张关键截图。

## 关键结论与可执行启发

仅提取视频中已有的结论、建议与适用条件；不推导用户账号的选题或传播策略。视频未提供可执行建议时如实说明。

1. 视频结论一：作者给出的适用条件与边界。
2. 视频结论二：视频明确说明的可执行动作。
3. 视频结论三：作者提到的风险、反例或限制。

## 待确认信息

| 缺口或冲突 | 对结论的影响 | 推荐补全方式 |
| --- | --- | --- |
| 听不清的口播 / 无法识别的画面 / 来源冲突 | 高、中或低 | 补字幕、补本地视频、补截图、接受当前结论 |

没有待确认项时，明确写“未发现影响主要结论的待确认信息”。

## 证据与处理说明

| 证据来源 | 使用范围 | 质量或限制 |
| --- | --- | --- |
| 页面章节 / 人工字幕 / ASR / 关键画面 | 支撑的内容部分 | 覆盖度、识别质量或冲突 |

说明本地保存的转录稿、JSON 证据和关键截图路径（如有）。使用 PeanutDL 下载时，同时记录原视频链接、对应下载页面和实际媒体文件路径；下载渠道不作为观点来源。时间戳仅用于溯源，不引导读者回看视频。

简要说明实际获取渠道与匿名会话方式（如无登录 HTTP、禁用外部配置的 yt-dlp、独立未登录浏览器）。未用浏览器时无需启动浏览器来验证。无法确认某条路线的隔离状态时，记录跳过原因。

内容未完全获取时，分别说明匿名访问、下载、音频提取、转写或画面识别中的失败阶段，避免把“文件下载成功”写成“内容已完整获取”。
```

## 后续创作选项（内容包之外）

内容获取完成后，可附一行：“后续可选：仅保留视频内容（默认） / 微信公众号文案 / 小红书文案 / 其他形式。”仅提供选项，不生成创作文案，也不将此选项写成内容包的必填章节。

用户已明确选择时，不再询问。将内容包、来源与待确认信息交给后续独立创作任务，沿用已获取的内容；创作文案不属于本 skill 的交付。批量作业不逐条展示选项。
