# 架构

## 设计目标

本仓库只收录由维护者维护、面向视频内容情报工作流的 Agent Skills。`SKILL.md` 是每项能力的跨平台入口；脚本、测试与参考资料随 skill 一起发布。

```text
skills/<skill-name>/
├── SKILL.md
├── scripts/
├── references/
└── tests/
```

`creator-intelligence` 负责多视频采集、排序与策略分析；`video-content-digest` 负责单条视频的字幕、转写与内容包生成。前者通过稳定的 `platform:video_id` 作业清单调用后者，不复制其下载和转写逻辑。

## 写入边界

安装目录只能读取。调用项目的 `.video-summary-radar/` 是唯一默认运行目录：

```text
.video-summary-radar/
├── runtime/    # 虚拟环境、模型、缓存与运行清单
└── outputs/
    └── 视频标题__平台-视频ID/
        ├── 口播稿.txt
        ├── 视频总结.md
        └── 处理资料/    # 身份记录、转录证据、媒体与日志
```

用户可显式指定其他输出或运行目录。未经确认，skill 不安装依赖、不下载模型、不修改系统级工具，也不删除任何运行数据。

## 同仓库开发与使用

开发源码可直接修改，已分发的安装副本仍按上述只读约定使用。本地个人任务可放在源码仓库的 `local-workspaces/<工作区名称>/`，默认运行目录随调用工作区确定：

```text
skills/                                      # 提交的源码
.agents/skills/                              # 忽略的本机源码发现入口
local-workspaces/<工作区名称>/               # 整体忽略的个人使用工作区
└── .video-summary-radar/
    ├── runtime/
    └── outputs/
```

源码验证从仓库根目录运行；真实采集和转写从对应使用工作区运行。`.agents/skills/` 可通过目录联接或符号链接直接引用源码，修改后无需重新安装。此布局不改变发布包结构，也不要求其他使用者携带维护者的个人工作区。

`prepare_output.py` 按平台、视频 ID 和分 P 复用目录，标题仅决定首次可读名称；本地文件使用内容散列。脚本只准备目录和来源记录，不生成空白稿件。TXT 导出默认拒绝覆盖不同内容；语义总结由 Agent 根据证据撰写，不能用脚本拼接摘要充当完整口播。

批量准备脚本在各 skill 可独立分发的前提下沿用同一命名规则，并在重复运行时保留既有路径与状态。策略解析器支持新版五章节总结及历史六章节内容包，缺失的钩子、互动或时间线保持为空；部分解析不计为完整成功样本。

## 跨平台与分发

正式支持 Windows、macOS 和 Linux。仓库优先遵循通用 Agent Skills 目录约定，通过 `npx skills add` 分发，并提供手动复制目录的兜底方式。专用插件市场仅在有明确维护需求时添加。
